# src/router — 강민호 책임

**② ROUTER — 어느 파서로 보낼지**

- 입력: `TriageResult + 파일`
- 출력: `ParserType + 처리 단위 목록`

## 먼저 — 판정 재료는 Triage 가 이미 채워 놓았다

`TriageResult.pages[]` 의 `PageInfo` 에 `has_text_layer` · `text_len` ·
`render_path` 가 들어 있다. 다시 탐침하지 않는다.

## 할 일

1. 엑셀 계열 → 포맷별 리더 분기 (`xlsx`/`xlsm` 는 openpyxl, `xls` 는 xlrd)
2. **페이지 단위로** 분기 — `PageInfo.has_text_layer` 를 보고 결정
3. tif → 전부 VLM
4. 판정 근거를 남긴다

## 실측 — 왜 페이지 단위인가

대상 909건의 포맷:

| 포맷 | 건수 | 비율 |
|---|---|---|
| `tif` | 734 | **80.7%** — 전부 스캔 |
| `pdf` | 108 | 11.9% |
| `xlsx`·`xlsm` | 67 | 7.4% |

PDF 108건의 내부 구성:

| | 건수 | 비율 |
|---|---|---|
| 전 페이지 텍스트 | 49 | 45.4% |
| **텍스트·스캔 혼재** | **56** | **51.9%** |
| 전 페이지 스캔 | 3 | 2.8% |

**파일 단위로 판정하면 절반이 틀린다.** 페이지 기준 텍스트 비율은 68.3% 다.

## 하지 말 것

- **파일 단위로 텍스트/스캔을 판정하지 말 것** — PDF 파일의 51.9% 가 혼재다
- 확장자만 보고 분기하지 말 것
- 임계값을 하드코딩하지 말 것 — `preprocess.TEXT_LAYER_MIN` (100자).
  20~500자 사이에서 판정이 거의 변하지 않으므로 튜닝은 불필요하다
  (텍스트 페이지 중앙값 2,055자, 스캔 0자대 — 사이가 비어 있다)
- 텍스트 레이어가 있다고 VLM 을 건너뛰지 말 것. 텍스트는 **글자를 보증**할 뿐이고
  **어느 값이 어느 필드인지는 VLM 이 정한다**. 실측: 텍스트 레이어가 온전한 PDF 에서도
  `OPEN`/`CLOSE` 가 한 덩어리로, 색상값이 라벨과 멀찍이 떨어져 나온다
