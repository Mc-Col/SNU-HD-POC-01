# src/parsers/vlm — 강민호 책임

**③-b VLM PARSER — 이미지에서 값과 위치를**

- 입력: `페이지 이미지 + 필드 정의`
- 출력: `RawExtraction[]`

## 할 일

1. 전처리 — 기울기 보정, 해상도 정규화
2. schema/fields.yaml 의 name·desc·aliases 를 프롬프트에 주입
3. 값 + bbox + confidence 를 함께 요구한다 (bbox 가 UI 하이라이트의 근거)
4. 문서에 없으면 raw_value=None 으로 정직하게 반환
5. 재시도 요청 시 bbox 크롭만 재판독

## 하지 말 것

- 재시도 프롬프트에 '값이 틀렸다'고 쓰지 말 것 — 환각을 유도한다.
-   올바른 문구: '이 영역에 문자 그대로 무엇이 적혀 있는지 보고하라. 같은 값이면 같다고 답하라'
- 없는 값을 추정해서 만들지 말 것

## 규칙

- 이 폴더 밖의 파일을 수정하지 않는다
- 계약은 `src/contracts.py` 를 import 해서 쓴다 (복사하지 않는다)
- 규칙·임계값은 `schema/*.yaml` 에서 읽는다
- fixture: `fixtures/vlm/`

## 🔧 이미지 크기 조정 — 켜기 전에 이 절을 읽는다

**해상도·업스케일·확대·크롭 관련 작업을 시작하기 전에 반드시 읽는다.**
스위치는 이미 있고 **기본은 전부 꺼져 있다.** 새로 만들지 말고 이것을 쓴다.

### 스위치

| 환경변수 | 기본 | 하는 일 |
|---|---|---|
| `D2S_LONG_EDGE` | `0` (끄기) | **목표 장변(px).** 원본이 크면 줄이고 작으면 키운다 |
| `D2S_UPSCALE` | **`2`** (확정 구성) | **배율.** 확대만 한다. 원본 크기에 종속된다. 끄려면 `1`. 상한은 `D2S_UPSCALE_CAP`(5000px) |
| `D2S_CROP_ZOOM` | `1` (끄기) | 재판독 크롭에 주는 추가 배율 |
| `D2S_PREP` | 없음 | `holes` = 펀치 구멍 제거 |

둘 다 설정되면 **`D2S_LONG_EDGE` 가 이긴다** (더 구체적인 지정이므로).

```
D2S_LONG_EDGE=2576 python -m eval.harness --stage vlm --only d001,d002 --emit runs/raw/시험명
```

### 포화점은 절대 장변 약 2500~2600px 이다 — 배율이 아니다

여러 세션이 서로 다른 방향·포맷·표본에서 같은 답에 도달했다.
**배율 모형은 두 번 반증됐고**(`pdf@1.50` 이 `tif@1.47` 과 같은 이득을 내지 않는다),
**절대 픽셀 모형이 모든 관측을 설명한다.**

```
장변     tif      pdf
1024   64.6%    77.4%
1753   70.4%      —
2339     —      85.7%
2576   76.0%    87.2%   ← 두 포맷 모두 최고
3506   75.7%    86.0%   ← 두 포맷 모두 꺾인다
```

| 구간 | 배율 | 맞댄칸 | 차이 | z | 판정 |
|---|---|---|---|---|---|
| tif 1753 → 2576 | 1.47 | 987 | **+5.6%p** | 4.04 | **유의** |
| pdf 2339 → 2576 | 1.10 | 663 | +1.5%p | 1.83 | 경계 미달 |
| tif 2576 → 3506 | 2.00 | 284 | −1.1%p | 0.54 | 차이 없음 |
| pdf 2339 → 3506 | 1.50 | 221 | +0.5%p | 0.33 | 차이 없음 |
| **2576 초과 → 2576** | 0.55 | 11문서 | **+8.83%p** | 3.00 | **유의 · 토큰 −62%** |

**축소도 이득이다.** 2576 을 넘는 PDF 11건을 내리면 정확도가 오르고(나빠진 문서 0건)
추출 칸이 늘고 입력 토큰이 62% 줄어든다 — **상충이 없다.** 확대(정확도↑ 비용↑)와
성격이 다르다.

### 아직 안 잰 것

| 대상 | 상태 |
|---|---|
| **terra 에서 2576 vs 3506** | **미측정.** 포화 모형은 `luna` 단독 결과다. 예비 측정(n=1)에서 `sol` 은 오히려 원본이 나았다 — **해상도 효과는 모델마다 방향이 다를 수 있다** |
| 초대형 DATA SHEET | `20FV904-DATA SHEET_REV0.pdf` 6892x9742 = 67.1MP. 텍스트 레이어가 0자라 대용 채점이 안 된다. **사양표라 정면 대상**인데 입력 토큰이 정상 문서의 14배다. 사람 라벨이 필요하다 |
| xlsx | 렌더가 `IndexError` 로 실패한다. 별건 |
| 2339~2576 · 2576~3506 세부 곡선 | 재지 않았다 |

### ⚠️ 켜기 전에 사용자에게 물어라

1. **팀 확정 구성을 덮는다.** 확정 구성은 `terra + 15규칙 + **2배 확대** + bbox + 포지셔너 차단`
   인데, `D2S_LONG_EDGE` 를 켜면 **`D2S_UPSCALE` 은 아예 읽히지 않는다.**
   2배(tif 3506)로 돌고 있다고 믿는 실행이 실제로는 1.47배로 돈다.
   포화 모형상 2576 이 낫지만 **그 판단은 `luna` 기준이고 확정 구성은 `terra` 다.**
2. **기본값으로 승격할 것인가, 실험 스위치로만 쓸 것인가.** 지금은 실험 스위치다 —
   `.env` 나 코드 기본값을 바꾸면 화면(`app.py`)·파이프라인 전체에 적용된다
3. **비용.** 확대는 토큰을 늘리고(tif 2,574 → 5,541) 축소는 줄인다(대형 79,056 → 5,541).
   포맷 구성에 따라 총액의 방향이 달라진다. `terra` 는 `luna` 의 10배다

**묻지 않고 켜지 않는다.**

### 실험할 때 지킬 것

- **캐시 키에 조건이 들어간다** (`imgfp` 에 `up`·`le`·`prep`·`dsk`).
  새 스위치를 추가하면 **반드시 키에도 넣는다** — 안 넣으면 조건이 다른데
  같은 응답을 재사용해 A/B 가 통째로 무력화된다
- **`--emit` 으로 원문을 남긴다.** 규칙이 바뀌어도 `--replay` 로 재채점이 0원이다
- **한 번에 하나만 바꾼다.** 두 개를 함께 켜면 어느 쪽 효과인지 못 가린다
- **홀드아웃을 확인한다.** `docs/TODO.md` 의 🔒 절을 먼저 읽는다.
  킷에 홀드아웃 표시 열이 없어서 `--only` 로 포맷을 지정하면 딸려 들어온다
