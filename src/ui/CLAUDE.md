- 입력: `DocumentResult`
- 출력: `승인 레코드 + 엑셀`

## 화면

| | 파일 | 하는 일 |
|---|---|---|
| 3 | `pages.py` | **쪽 고르기** — 사람이 사양표를 지목한다. 분류하지 않는다 |
| 5 | `hitl.py` | 검증 — 좌 지면+bbox / 우 항목표 · 표시원 배지 |
| 6 | `approve.py` | **사전 승인** — 어휘 밖 값을 실행 단위로 한 번에 |

## 할 일

1. 좌측 원본 이미지 / 우측 항목 표 (화면정의서 기준)
2. 항목을 선택하면 bbox 영역 하이라이트 (초록 실선 정상추출 / 노란 점선 확인필요)
   — 화면정의서의 '마우스 오버'는 Streamlit 에 hover 이벤트가 없어 '행 선택'으로 대체함
3. 정상추출은 패스, 확인필요·N/A 는 개별 확인 강제
4. 필수 필드가 모두 해소되면 '검토 완료' 활성화 (DocumentResult.approvable)
5. [Cv 계산] 버튼 — RATED CV 가 N/A 일 때 공정조건으로 계산 제안
6. 엑셀 export

## 하지 말 것

- 검증 세션 전체 소요시간은 스톱워치로 수동 측정 (자동 로깅은 MVP 범위 외)
- **검증기를 직접 조립하지 말 것.** 표시원은 `src.validate.domain.check_all` 하나에서만
  나온다. 화면과 평가 하네스가 각자 조립하면 "화면에서 본 것과 채점된 숫자" 가 갈린다
- **표시(Flag)를 저장하지 말 것.** (값·추출·문맥·규칙)의 파생물이고, 저장하면 규칙이
  바뀔 때 낡은 채로 남는다. `UiDoc.flags(rec)` 가 매번 다시 계산한다
- **`schema/rules.yaml` 을 쓰지 말 것.** 승인 결과는 `runs/.../vocab_approved.yaml` 에
  조각으로 두고 병합은 사람이 한다
- **쪽을 자동 분류하지 말 것.** 사양표 판정은 사람이 한다 (2026-08-25 결정).
  텍스트 레이어가 있으면 날짜·개정표기를 배지로 붙여주는 것까지가 화면의 몫이다
- **값을 자동 교정하지 말 것.** 재질·안전 필드(`correctable=False`)에는 "다른 표기"
  선택지를 노출하지 않는다 — `CS`→`C5` 는 탄소강을 크롬몰리강으로 바꿔치기하는 일이다

## 규칙

- 이 폴더 밖의 파일을 수정하지 않는다
- 계약은 `src/contracts.py` 를 import 해서 쓴다 (복사하지 않는다)
- 규칙·임계값은 `schema/*.yaml` 에서 읽는다
- bbox 는 **정규화(0~1)** 다 (계약). 화면이 페이지 크기를 곱해 그린다
- fixture: `fixtures/ui/` — 합성 지면은 픽스처에서 생성한다: `python fixtures/ui/make_sample.py`
- 자기검증: `python -m pytest src/ui -q`  (22건)
- 다중 페이지 픽스처 `sample_multipage.pdf` — 사양표 2장 · 폐기 표시는 손글씨라
  텍스트 레이어에 없다. 쪽 고르기 비교 뷰를 시험하는 유일한 수단이다
- 화면에서 필드·필수여부·임계값·상태를 정의하지 않는다. 계약과 yaml 에서만 읽는다
