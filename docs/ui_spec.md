# 화면 사양 — PoC 시연용

최종 갱신 2026-08-25 · 발표 2026-08-27

이 문서는 **다른 세션에서 화면 작업을 시작할 때 읽는 것**이다. 결정의 배경은
`ARCHITECTURE.md`, 측정 숫자는 `eval_history.md`, 판단 근거는 `insight_memory.md`.

---

## 왜 화면이 중요해졌나

**쪽 선택을 사람이 하기로 정했다** (2026-08-25). 그러면 화면은 있으면 좋은
것이 아니라 **파이프라인의 일부**가 된다.

이 결정의 근거 세 가지 —

1. **비용** 자동 선별은 문서당 약 3,500 입력 토큰이다. 1,021건이면 약 360만
   토큰이고 전체 추정의 1/3이다. 그것이 통째로 사라진다.
2. **정직성** 지금까지 정확도에는 *"쪽을 사람이 알려준 상태의 숫자"* 라는
   단서가 붙었다. **사람이 고르는 것이 설계라면 그건 결함이 아니라 사양**이다.
3. **일관성** 사람은 이미 ⑦에 있다. ①에도 두는 것이 같은 원리다.

그리고 임원이 판단하려는 것은 처리량 표가 아니라 **"이게 실제로 쓸 물건인가"**
다. 전수 실행과 화면은 다른 질문에 답한다.

## 화면 1 — 쪽 고르기 (신규 · 최우선)

```
업로드 → 쪽 이미지 렌더 → 사람이 사양표 지정 → 추출
```

**기본 동작** 모든 쪽을 축소 이미지 격자로 띄우고 사람이 하나를 고른다.
도구는 이미 있다 — `preprocess.render_pages` · `make_montage`.

**⚠ 후보가 2장 이상이면 축소 이미지로는 못 가린다**

`10FV011` 이 실증이다. 사양표가 2장인데 하나는 2003년 개조본, 하나는 1986년
원본이고 **원본에는 손으로 `OLD` 라고 적혀 있다.** 축소하면 그 글씨가 안 보인다.
그리고 이건 **숙련자도 틀린 케이스**다 — 처음에 "태그가 단독인 쪽" 으로
판단했다가 뒤집었다.

→ 후보가 둘 이상이면 **날짜·개정표기를 뽑아 나란히 크게** 보여준다.
   `preprocess.parse_doc_date` · `find_marks` 가 이미 그 일을 한다.
   텍스트 레이어가 있으면 공짜이고, 없으면 후보에만 작은 호출 한 번이다.

**공짜로 얻는 것 — 자동 선택의 정확도**

사람이 고를 때마다 **"규칙으로 골랐으면 같은 답이었나"를 조용히 기록**한다.
그러면 자동 선택 정확도가 **사람이 일하는 동안 측정된다.** 나중에 자동화할 때
근거가 이미 쌓여 있다. 추가 토큰이 들지 않는다.

## 화면 2 — 추출 결과 (기존 보강)

**3-상태를 눈으로 구분되게**

| 상태 | 뜻 | 사유 |
|---|---|---|
| 자동확정 | 규칙·확신도 통과 | 선택 (안전·식별 필드는 확인 표시) |
| 확인필요 | 아래 표시원 중 하나 이상 | **필수** |
| 근거없음 | 문서에 값이 없다 | **필수** |

**표시원을 구분해서 보여준다** — 어느 수단이 이 칸을 불렀는지가 보여야
사람이 무엇을 확인할지 안다. 2026-08-25 실측 기준 —

| 표시원 | 칸 | 비용 | 뜻 |
|---|---|---|---|
| 확신도 | 90 | 0원 | 흐리게 읽었다 |
| 어휘 | 22 | 0원 | 허용 어휘 밖이다 |
| 출처 | 2 | 0원 | 더 나은 출처를 두고 로고를 읽었다 |

**원문과 표준값을 함께** `CLASS 4 → CLASS 4` 처럼 안 바뀐 것은 하나만,
`EQ% → EQUAL PERCENTAGE` 처럼 바뀐 것은 둘 다. 감사 시트에도 원문이 남는다.

**bbox 하이라이트는 이미 동작한다** (`src/ui/overlay.py`). 다만 실물에서
**한 행 어긋나는 경우**가 있다 — 알려진 한계다.

## 화면 3 — 사전 승인 (신규 · Loop C 의 입구)

**이것이 이 과제를 도구가 아니라 시스템으로 만든다.** 사람이 한 번 판단하면
그 판단이 규칙 파일에 남아 다음부터 자동으로 적용된다.

데이터는 이미 나온다 — `src/validate/domain/vocabulary.as_rows()`.

```
| 필드 | 값 | 건수 | 문서 | 원문 항목명 | 가장 가까운 허용값 |
```

**지켜야 할 것 넷**

1. **실행이 끝난 뒤 한 번에** 보여준다. 문서마다 물으면 1,021건에서 수백 번
   클릭이 되고, 그러면 읽지 않고 승인하게 된다 — 승인이라는 안전장치가
   형식만 남는다.
2. **빈도순**으로 정렬한다. 40건에서 나온 표현은 볼 가치가 있고 1건짜리는
   스캔 잡티일 수 있다.
3. **기본값은 "무시"** 다. 승인이 의도적 행위여야 한다.
4. **가장 가까운 허용값은 보여주기만** 한다. 자동으로 고치지 않는다 —
   `C5`(Cr-Mo 합금강)와 `CS`(탄소강)는 한 글자 차이지만 다른 재질이고,
   사용 온도 한계가 다르다.

승인된 것은 `schema/rules.yaml` 로 간다. **기계가 자동으로 쓰지 않는다** —
모델의 오독이 영구 규칙이 되고, 규칙 파일이 "도메인 전문가가 읽고 고치는
산출물" 이라는 성질을 잃는다.

## 화면 4 — 엑셀 내보내기 (기존)

`src/ui/export.py` 가 이미 한다. **열 순서는 계약**이다 —
`readme/output_sample.xlsx` 의 DB CODE 순서를 따른다.

감사 추적은 **별도 시트**에 둔다. Output 시트의 모양을 바꾸지 않기 위해서다.

## 손대면 안 되는 것

- `src/contracts.py` · `schema/*.yaml` · `src/pipeline.py` · `src/hooks.py` ·
  `src/preprocess.py` — 소유자만 수정한다. 필요하면 요청한다.
- **재시도 프롬프트에 "값이 틀렸다"고 쓰지 않는다.** 환각을 유도한다.
- **제약 위반에 재시도를 걸지 않는다.** 재시도는 추출 실패(못 읽음)에만.
