## 1. 데이터 흐름

```
파일 ─▶ ① Triage ─▶ ② Router ─▶ ③ Parser(Text|VLM) ─▶ ④ Normalize
     ─▶ ⑤ Validate(형식→도메인→평가Agent) ─▶ ⑥ State ─▶ ⑦ HITL ─▶ 엑셀
```

계약은 `src/contracts.py` 세 개뿐이다.

| 계약 | 만드는 곳 | 뜻 |
|---|---|---|
| `TriageResult` | ① | 이 파일에 데이터가 있나, 어느 페이지를 볼 것인가 |
| `RawExtraction` | ③ | 문서에서 읽은 값 하나 — 원문·위치·확신도 |
| `FieldRecord` | ④⑤⑥ | 최종 1필드 — 값·상태·근거·비고 |

이 셋 밖의 자료구조는 모듈 경계를 넘지 않는다.

### 루프 세 개

| | 주기 | 무엇 | 없으면 |
|---|---|---|---|
| **Loop A** | 초 | 필드 단위 재추출 (못 읽은 값만) | 한 글자 때문에 문서를 다시 돈다 |
| **Loop B** | 분 | 문서 배치 처리 | — |
| **Loop C** | 일 | 사람의 수정을 규칙으로 되돌림 | **스크립트지 하네스가 아니다** |

Loop C 의 입구가 `on_rule_edit` 훅이다. 사람이 판단 기준을 글로 남긴 순간이 개선의 원재료다.

## 2. 3-상태 모델

| 상태 | 뜻 | `note` |
|---|---|---|
| `AUTO` | 자동 확정 | 안전·식별 필드는 그래도 사람 확인 표시 |
| `REVIEW` | 확신도 미달 또는 규칙 위반 | **필수** |

`FieldRecord.validate()` 가 `note` 없는 비-AUTO 를 거부한다. 근거 없는 값을 만들지 않는 것이 이 과제의 존재 이유다 — 추정값이 마스터DB 에 들어가면 없애려는 문제를 재생산한다.

### 확신도 임계

| 분류 | 임계 | 필드 |
|---|---|---|
| `safety` | 0.95 + **사람 확인 필수** | `actuator_fail_action` |
| `identity` | 0.95 + **사람 확인 필수** | `engineering_tag_no` |
| `normal` | 0.90 | 나머지 |

안전 필드를 영구 REVIEW 로 잠그지 않는다 — 자동 확정하되 확인 표시를 남긴다. 1.00 임계는 "자동확정 + 사람 확인" 설계와 모순이었다(C0xx).

### 비용 사다리

```
규칙 검증(무료) ─▶ 평가 Agent(유료) ─▶ HITL(가장 비싸다)
```

앞 칸을 건너뛰지 않는다. VLM 에 판단을 넘기기 전에 항상 "이건 규칙으로 되나?" 를 먼저 묻는다.

## 4. 결정된 규칙

### 4.1 태그 — Area 는 문자+숫자, 생략은 A

```
Area - 설비종류 - 일련번호        A10-FV-001 · B10-PV-1631A
 └ 문자+숫자   └ FV·PV·LV…     └ 숫자(+접미)
```

앞 문자는 공장이고 **없으면 A 가 생략된 것**이다. 1공장이 최초 공장이라 지을 때 구분이 필요 없었고, 2공장부터 B 를 붙였다.

**정규화 키와 내보내는 값을 분리한다.**

| | 값 | 용도 |
|---|---|---|
| `TagParts.key` | `A10FV011` | 파일명↔문서 대조, 페이지 검증 |
| `TagParts.raw` | `10FV011` | 화면·엑셀 표시 |
| `implicit_plant` | `True` | A 를 규칙으로 채웠다는 표시 |

**내보내는 값은 문서에 적힌 그대로다.** 없는 A 를 만들어 넣지 않는다. 마스터DB 에 정식 표기로 저장하는 것은 to-be.

키에 공장 문자를 항상 넣는 이유: 없으면 `10-FV-012`(A10)와 `B10-FV-012`(B10)가 같은 값이 되어 서로 다른 설비가 합쳐진다. 현 코퍼스 충돌 0건이지만 30만 태그에서는 터진다.

**나열 표기를 펼친다** — `10-FV-011 / 012 / 013 / 014` → 4개. 다중 설비 사양표의 태그 대조가 이 형태다. 자리수가 같은 번호만 이어 붙인다(`/ 2003` 을 태그로 보지 않기 위해).

**예외 — B19 구역** 2공장은 미국 설비를 그대로 들여와 원 공장 태그를 쓴다. 도면 호환 때문에 Area 만 앞에 붙였다(`B19V10` = B19 구역의 `V10`). 실측 2건. 규칙을 느슨하게 풀어 잡지 않는다 — 설비종류 1자를 허용하면 스프링번호 `1E7924` 류가 대량으로 태그가 된다.

### 4.2 페이지 선택 — 최신성

한 파일에 사양표가 여러 장이면 **가장 최신인 한 장**만 본다.

```
① 격자 1장 → VLM 이진 판정: 어느 페이지가 사양표인가        (호출 1회)
② 후보 1장이면 확정
③ 2장 이상이면 후보만 원본 해상도로 렌더 → 날짜·개정표기 읽기
   a. 폐기 표기(OLD·SUPERSEDED·VOID·폐기) 있는 후보 제외
   b. 남은 것 중 연도 최신
   c. 연도 같으면 월·일 (순서 모호한 날짜끼리는 비교 안 함)
   d. 날짜로 못 가리면 RETROFIT / AS-BUILT / REVISED 표기
   e. 그래도 못 가리면 **고르지 않는다** → 확인필요, 사람이 선택
④ 선택된 페이지의 태그 목록에 파일명 태그가 없으면 확인필요
```

8페이지를 VLM 8회가 아니라 **2~4회**로 처리한다.

**날짜는 4자리 연도가 없으면 날짜로 보지 않는다.** 실물 헤더에 `Quote No. 85-1874` 와 `Date 9/6/1986` 이 나란히 있고 `QUOT 11/1/85` 도 있다. 2자리 연도를 허용하면 견적번호·`REV1`·팩스헤더가 전부 날짜가 된다.

**태그 단독성은 선택 기준이 아니다.** `10FV011` 은 사양표 2장인데 p1 이 4개 태그를 담은 2003년 Retrofit 사양서, p4 가 단독 태그의 1986년 원본(수기 "OLD")이다. 단독성으로 고르면 `MODEL NO.`(657-ED vs 667-ED)와 `RATED CV`(70.7 vs 95)가 틀린다. 태그 대조는 **선택 후 검증**에만 쓴다.

### 4.3 범위

| | 범위 |
|---|---|
| 한 파일 안에 사양표 여러 장 → 어느 것이 최신? | **범위 안** |
| 한 설비에 파일 여러 개 → 어느 파일이 정답? | **범위 밖** |

이번 과제의 질문은 **"개별 파일을 넣었을 때 추출이 되는가"** 다.

**정비·개조 보고서 112건 제외** — 난이도가 아니라 내용 부재가 이유다. `CONTROL VALVE REPAIR & RETROFIT CHECK SHEET` 의 SPECIFICATIONS 칸은 사양서가 아니라 작업 기록이다.

| | 15FV031 | 10PCV072 |
|---|---|---|
| 사양 22칸 중 기재 | 12칸 | **2칸** |
| `RATED CV` · `MODEL NO.` | 공란 | 공란 |

두 번째 이유 — 시점이 섞인다. `15FV031` 은 `MODEL NO.`·`RATED CV` 가 1986년 원본(p8)에, 포지셔너 `DVC 6200` 이 2022년 체크시트(p7)에 있다. **페이지 선택이 아니라 페이지 병합 문제**다. 보고서를 빼면 "파일 안에서 한 페이지를 고른다" 규칙이 유지된다.

제외는 구멍이 아니라 **측정 항목**으로 둔다 — `scope_reason()` 이 사유를 남기고, 골든셋에 정비보고서를 "제외가 정답" 으로 넣어 Triage 가 추출을 시도하지 않는지 채점한다.

### 4.4 VLM 과 텍스트 레이어의 역할

**VLM 이 어느 텍스트가 어느 필드인지 정하고, 텍스트 레이어가 그 글자를 보증한다.**

텍스트 레이어를 "VLM 을 건너뛰는 지름길" 로 쓰지 않는다. 실측 근거: 정비보고서 p2 는 텍스트 레이어가 온전한데 뽑아보면 `OPEN`/`CLOSE` 가 한 덩어리로, `Silver`/`Green`/`Green` 이 라벨과 멀찍이 떨어져 나온다. 글자는 100% 있지만 어느 값이 어느 필드인지 알 수 없다. 표 구조가 무너진 텍스트는 값의 목록일 뿐이다.

비용 절감은 **페이지 수를 줄이는 데서** 얻고, 판독 단계를 생략해서 얻지 않는다.

### 4.5 재시도

- 재시도는 **추출 실패(못 읽음)** 에만. 제약 위반에는 걸지 않는다.
- 재시도 프롬프트에 "값이 틀렸다" 고 쓰지 않는다 — 환각을 유도한다.
  올바른 문구: *"이 영역에 문자 그대로 무엇이 적혀 있는지 보고하라. 같은 값이면 같다고 답하라"*

### 4.6 단위 표기

숫자만 대조한다. 옛 데이터시트는 단위를 사람이 손으로 썼고 `H`·`Hr`·`hr` 이 전부 Hour 다. 표기 변형을 감점하지 않는다.

### 4.7 알려진 함정

| 함정 | 실물 |
|---|---|
| **하단 회사명 ≠ 제조사** | 10FV011 하단 `VALSTONE SERVICE, CO.` 는 시공사. 제조사(Fisher)는 Note 의 한국어 문장에 있다. 반대로 10FV079 Metso 는 하단이 실제 제조사 — 문서 성격(RETROFIT/REPAIR)으로 갈린다 |
| **ATO/ATC 역전** | `Air-to-Open` → FAIL **CLOSE**(역전) / `Air Fails Valve to Open` → FAIL **OPEN**(직접). 판별자는 `Fails` 의 유무 |
| **모델명은 결합 표기** | `667-EZ`·`GU-VDR`·`667-ED` — 앞이 액추에이터, 뒤가 본체. 쪼개지 않는다 |
| **Positioner Type ≠ 모델명** | `ELEC. PNEUMATIC` 은 구분값. 모델명은 `AVP-302` |
| **파일명 문서종류가 거짓** | `B19V10-DATA SHEET_REV1.xlsx` 의 내용은 2010년 TA Retrofit 체크시트 |

## 8. `src/preprocess.py` — 공용 전처리 도구

판정 로직을 넣지 않는다. **사실만 수집하고 판정은 각 모듈이 한다.**

| 함수 | 하는 일 |
|---|---|
| `parse_filename(path)` | 태그·문서종류·rev → `FileNameInfo` |
| `parse_tag(s)` · `normalize_tag(s)` | 태그 쪼개기 · 정규화 키 |
| `find_tags(text)` | 텍스트에서 태그 전부 (나열 펼침) |
| `scope_reason(path)` | 제외 사유 문구 |
| `probe_pages(path)` | 페이지별 텍스트 레이어 유무·글자수 |
| `render_pages(path, out, dpi, pages)` | tif/pdf/xlsx → 페이지별 PNG. 선택 렌더 |
| `make_montage(pngs, out)` | 썸네일 격자 (VLM 이진 판정용) |
| `parse_doc_date(text)` · `find_marks(text)` | 날짜 · 개정/폐기 표기 |
| `pick_latest_spec(pages, file_tag)` | 최신 사양표 선택 + 사유. 못 가리면 `None` |
| `index_by_tag` · `staleness_warning` | **파이프라인 미사용** — 코퍼스 통계용 |

### 렌더링 결정

- **PNG, JPG 아님** — 1비트 150DPI 손글씨 스캔에서 JPG 잡티가 판독을 방해한다. 1비트는 그레이스케일로 올려 렌더
- **기본 200 DPI** — 원본이 150DPI 1비트라 그대로 쓰면 손글씨가 뭉개진다
- **엑셀은 시트 1개 = PNG 1장** — 통째로 내보내면 5시트가 인쇄면 13장이 되어 `probe_pages()` 의 시트 번호와 어긋난다(계약 버그). 엑셀의 의미 단위는 인쇄면이 아니라 시트다
- **격자는 12칸씩 분할** — Claude 는 긴 변 1568px 초과 시 이미지를 줄인다. 61페이지를 한 장에 담으면 셀이 224px 가 되어 판독 불가. 3×4=1440px 가 한계 안 최대치
- **격자 480px 셀에서 사양표·도면·부품리스트·표지·계산서가 구분된다**(실물 확인). 단 **태그 글자는 안 읽힌다** — 종류 판정까지만 쓰고 태그 대조는 원본 해상도에서 따로 한다
- **엑셀 렌더 실패는 예외를 던지지 않는다** — 빈 목록을 돌려주고 Triage 가 판정한다

## 10. 평가

- **홀드아웃 잠금** — 골든셋 30건 중 일부는 개발 중 보지 않는다
- **`--no-vlm`** — API 없이도 텍스트 경로만으로 측정
- **3-way A/B** — 텍스트 단독 / VLM 단독 / VLM+텍스트
- **숫자만 대조** — 단위 표기 변형은 감점하지 않는다
- **제외가 정답인 케이스 포함** — 정비보고서를 데이터시트로 착각하지 않는지
- **rule of three** — 100건에서 오류 0건이면 95% 상한이 약 3%. **100% 정확도는 증명할 수 없다**

같은 입력 → 같은 출력. 난수·시각에 의존하지 않는다. 개선을 측정할 수 없게 된다.
