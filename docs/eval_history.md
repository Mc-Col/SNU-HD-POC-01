## 상위 모델(terra) 2차 판독 — 판단

**질문** — 상위 모델을 붙이면 비용을 정당화할 만큼 좋아지는가. 4R·5R 이 이것을 재려고 돌린 실행이다.

| | 4R (크롭 결함) | 5R (크롭 수정) |
|---|---|---|
| 최종 정확도 | 87% (84/97) | **93%** (90/97) |
| 승격 대상 | 23칸 | 23칸 |
| 두 모델 일치 | 17 | **19** |
| 값 변경 | 6 | **1** |
| 2차 판독 실패 | 0 | 3 |
| 값이 바뀐 것의 효과 | 개선 0 · 악화 3 · 변화없음 3 | 개선 0 · **악화 1** · 변화없음 0 |
| terra 비용 | 10,880 / 4,238 | 13,126 / 1,287 |

**4R 의 -5칸은 모델 탓이 아니었다.** `_crop()` 이 왼쪽 라벨 칸을 잘라내고 있었다. 전체 페이지를 본 1차는 `Tag` 라벨을 볼 수 있었고, 크롭을 받은 2차는 볼 수 없었다 — 더 좋은 모델에게 더 나쁜 문제를 준 것이다. 크롭을 고치자 87% → 93% 로 회복했다(인사이트 51).

**그러나 크롭을 고쳐도 상위 모델은 값을 하지 못했다.** 5R 에서 —

- **23칸 중 19칸은 두 모델이 같은 값을 읽었다.** 확신은 얻었지만 값은 그대로다. 비용은 전액 들었다.
- **3칸은 2차가 아예 읽지 못했다.** 1차를 유지했으니 손해는 없지만 이득도 없다.
- **유일하게 값이 바뀐 1칸은 악화였다.** `d008 actuator_fail_action` 이 `Open`(정규화대기 — 맞는 칸을 집었고 규칙 한 줄만 남았다) 에서 `Close`(오답) 로 바뀌었다. **안전 필드에서 페일 방향이 뒤집혔다.**

**3R(luna 단독) 92% 대비 5R 93% 의 +1칸은 terra 의 공이 아니다.** terra 가 손대지 않은 칸에서 왔다 — `d003 model_no` · `d001 required_cv` 가 실행 간 편차로 달라졌다. 같은 프롬프트·같은 이미지인데 답이 달랐다(인사이트 53).

**판단** — 현재 승격 조건(안전·식별 필드 + 확신도 미달 + 태그 불일치)으로는 **상위 모델이 비용을 정당화하지 못한다.** 얻은 것은 19칸의 일치 확인이고, 그것은 정확도가 아니라 **확신**이다.

다만 표본이 작다. 값이 바뀐 칸이 4R 6칸 · 5R 1칸이므로 "상위 모델이 더 나쁘다" 고 단정할 근거는 없다. 말할 수 있는 것은 두 가지다 — ① **일치율 83%(19/23)** 는 표본이 작아도 견고한 숫자이고, 이것이 비용 논거다. ② **개선 사례가 아직 0건이다.**

**결론** — 승격을 정확도 수단이 아니라 **확신 수단**으로 재정의한다. 값을 자동으로 바꾸지 않고(자동확정 금지는 이미 `escalate.settle` 에 있다), 두 판독이 다르면 사람에게 넘긴다. 안전 필드에서 방향이 뒤집힌 5R d008 이 그 이유다. 개선 사례가 나오면 그때 정확도 수단으로 승격한다.

    d036 tif 79%   d037 tif 86%   d038 tif 71%   d039 pdf 68%   d040 xlsx 93%

### 실행 중 정정 1건 — 쪽 지정 오류

`d040` 은 처음에 **46%** 였다. 킷의 사양표 페이지가 `1`(Report 표지)로 적혀
있었고, 실제 사양표는 시트 `3`(TEST)이다. **모델에게 표지를 주고 사양을 물었다.**
쪽을 고쳐 재실행하니 **93%** 가 됐고 미추출이 14 → 0 이 됐다.

이것은 **규칙을 결과에 맞춘 것이 아니라 입력 오류를 고친 것**이라 블라인드는
유지된다. 그리고 이 사건 자체가 *"사람이 화면에서 쪽을 고른다"* 는 설계 결정의
근거다 — 운영에서는 썸네일을 보므로 표지를 고를 일이 없다.

### 격차의 원인 — 규칙 과적합이 주범이 아니다

오류 30건을 원인별로 갈랐다.

| 원인 | 건수 | 성격 |
|---|---|---|
| **열 선택** (Min/Normal/Max 블록에서 다른 칸) | 8 | 구조적 약점 |
| **미추출** (`d039` 한 건에 7건이 몰림) | 10 | 문서 편차 |
| **정답지 표기** (`14.000`=1만4천 · `.138` · `(MAX)`) | 5 | 모델 잘못이 아니다 |
| **지어냄** (정답 N/A 인데 값 생성) | 4 | 진짜 문제 |
| **오독** (`QUENCH`→`SUCTION` · `219.55`→`20.55`) | 3 | 진짜 문제 |

필드별 격차 상위가 **전부 공정 조건**이다.

    normal_flow_rate    90% → 20%   (-70%p)
    normal_pressure    100% → 60%   (-40%p)
    specific_gravity    76% → 40%   (-36%p)

어느 열을 집느냐의 문제다.** 개발셋 21건이 이 축의 난이도를 과소표집했다 —
