원문을 확인한 결과 rev.1 에 틀린 서술이 있었다. 넷 다 결론을 바꾸므로 먼저 적는다.

| # | rev.1 서술 | 원문 확인 결과 |

| 2 | 텍스트 verbatim 대조가 "추가 API 비용 0원" | **범위를 잘못 썼다.** tif 734건(71.9%)에는 텍스트 레이어가 **아예 없다.** 이 신호는 PDF 텍스트 페이지·xlsx·정비보고서에만 붙는다. 주 경로에 붙이려면 **로컬 OCR 엔진 추가**가 필요하다 |
| 3 | 로그확률 포화(99.4~100%)를 "우리도 정확히 이 조건" | **과장이다.** 그 관찰은 GPT-4.1-mini 가 **yes/no 단일 answer 토큰**을 낼 때의 조건이다. 우리는 문서에서 뽑은 문자열을 낸다. 우리 조건에 더 가까운 수치는 ExtractConf 의 **로그확률 평균 AUC 0.705** 다 — 약하지만 무의미하지는 않다 |
| 4 | olmOCR document anchoring 을 강한 근거로 제시 | **정량 ablation 이 논문에 없다.** "환각이 뚜렷이 줄었다" 는 정성 주장뿐이다. 게다가 저자는 **텍스트 레이어가 없는 스캔에서는 anchoring 없이 이미지에만 의존한다**고 명시한다 |

정정 2 와 4 가 같은 곳을 가리킨다 — **우리 코퍼스의 71.9% 를 차지하는 tif 스캔에는,
"텍스트로 글자를 보증한다" 는 장치가 지금 존재하지 않는다.** 이것이 이 조사의 핵심 발견이다.

## 1. 요약 — 실제 개선이 가능한가

**가능하다. 단 세 갈래로 나뉜다.**

| | 무엇 | 왜 그렇게 판정했나 |
|---|---|---|
| **즉시 가능 (○)** | ① 임계를 골든셋 곡선으로 재결정 ② 문서전체 추출 ↔ 크롭 재판독 **교차 일치**를 신뢰도 신호로 ③ 평가Agent 를 '채점자' 형태로 배치 | 추가 의존성 없음. 우리 코드에 재료가 이미 있음 |
| **조건부 (△)** | ④ 텍스트 verbatim 대조 ⑤ 텍스트 앵커링 | **텍스트 레이어가 있는 문서에만** 붙는다. 대상은 xlsx 118건 + PDF 텍스트 페이지 + 정비보고서 111건. tif 734건은 제외 |
| **보류 (×)** | ⑥ 로컬 OCR 엔진 추가 ⑦ 다중 모델 앙상블 ⑧ Claude Citations ⑨ 로그확률 신호 | 새 의존성·새 실패모드·발표까지 3일. ⑧은 기술적으로 불가 |

**가장 확실한 한 가지**를 고르라면 ②다. ExtractConf 의 Hunter/Mapper 구조가 우리
`extract()` / `reread()` 와 **구조적으로 같은데, 우리는 둘을 비교하지 않고 있다.**

**새로 발견한 리스크 하나** — 최신 프론티어 모델도 문서에서 bbox 를 제대로 찍지 못한다
(Gemini-2.5-Pro 기준 **IoU 14.4%**). 우리 UI 하이라이트와 크롭 재판독이 모두 bbox 를
전제한다. §5 에 대응책을 적었다.

### R1. ExtractConf — 문서 필드 추출 전용 신뢰도 엔진
[arXiv:2606.24420](https://arxiv.org/abs/2606.24420) · 이 조사에서 가장 중요한 논문

**무엇을 한 연구인가.** LLM 이 문서에서 뽑은 값 하나하나에 대해 "이 값을 믿어도 되는가" 를
점수로 매기는 엔진. 로그확률 하나만 쓰지 말고 **5개 신호군 40개 특징을 합성**하자는 것.

**실험 조건**

| 항목 | 값 |
|---|---|
| 데이터 | DocILE — 실제 비즈니스 **인보이스** 6,680건, 55개 필드 범주 |
| 학습/평가 | 필드 단위 표본 **1,072 학습 / 267 평가** (별도로 CORD 영수증 828표본 zero-shot) |
| 추출 모델 | **GPT-4o**, `temperature=0.0`, `logprobs=True`, `top_logprobs=5` |
| OCR | **AWS Textract** — 단어별 confidence + bbox 제공 |
| 결합 모델 | **CatBoost 이진 분류기** (depth 8, lr 0.1, l2 7, 1000 iterations) |
| 자연 실패율 | 26% (즉 LLM 추출값 4개 중 1개가 틀린 상태에서 시작) |

**두 개의 추출 호출 — Hunter 와 Mapper**

- **Hunter (필드 주도)** — *"이 문서에서 필드 f 의 값을 뽑아라"*. 값 + 토큰별 로그확률 +
  주변 텍스트를 돌려준다. 저자 표현: *"완성 압박(completion pressure) 아래 있어서, 그 필드가
  문서에 분명히 있든 없든 답을 만들어낸다 — 없거나 애매한 필드에 그럴듯한 값을 지어내기 쉽다."*
- **Mapper (문서 주도)** — *"문서를 통으로 훑어 각 대상 필드에 대해 가장 두드러진 후보값을
  찾아라"*. 저자 표현: *"시각적으로 근거가 있는 것만 보고한다(reports only what is visually
  grounded)."*

이 둘의 **불일치가 곧 위험 신호**다.

**신호 5군 40특징**

| 군 | 내용 | 특징 수 |
|---|---|---|
| G1 | 토큰 로그확률(평균·최소·10퍼센타일·표준편차) + 섀넌 엔트로피(평균·최대·90퍼센타일) | 14 |
| G2 | **추출값이 원본 OCR 텍스트에 문자 그대로 있는가**(이진) + OCR 유사도 임계 50/75/90% + 라벨·값 OCR 신뢰도 | 12 |
| G3 | **Hunter 와 Mapper 값의 일치** — 완전일치 여부 + 유사도(필드 타입에 따라 Levenshtein 또는 FuzzyWuzzy) | — |
| G4 | 라벨 근접 매칭 점수, bbox OCR 신뢰도, 중심점 거리, **정규화 라플라시안 점수(이미지 선명도)** | 8 |
| G5 | 필드 타입 원-핫(숫자·날짜·제한텍스트·자유텍스트·영숫자) | 5 |

**수치 (DocILE 평가셋)**

| 구성 | AUC | AURC | ECE | Brier |
|---|---|---|---|---|
| B1 로그확률 평균만 | 0.705 | 0.145 | 0.245 | 0.253 |
| B3 self-consistency 5회 | 0.744 | 0.138 | 0.075 | 0.183 |
| M1 로그확률 + 엔트로피 (G1) | 0.880 | 0.076 | 0.180 | 0.162 |
| **M4 OCR 근거만 (G2)** | **0.896** | 0.079 | 0.197 | 0.141 |
| M6 전체 결합 | **0.928** | 0.043 | 0.199 | 0.136 |
| M7 = M6 + isotonic 보정 | 0.926 | 0.044 | **0.034** | 0.094 |

운용 지표 — **커버리지 80% 에서 자동화 정확도 99.1%** (선별 없는 기준선 73.3% 대비
+25.8%p).

**우리와 다른 점**

| | 논문 | 우리 |
|---|---|---|
| 문서 | 영문 인보이스 (born-digital 다수) | 1986~2022년 한영 혼재 컨트롤밸브 데이터시트, **1비트 150DPI 팩스 스캔 다수** |
| OCR | AWS Textract 단어별 confidence | **없음.** PDF 텍스트 레이어만 있고 tif 71.9%는 그마저 없음 |
| 라벨 데이터 | 1,072 필드 표본 | 골든셋 30문서 × 28필드 = **최대 840**, 홀드아웃 제외하면 더 적고 N/A 비중이 큼 |
| 결합 방식 | CatBoost 학습 | 학습 표본이 부족 |

**이식 판정**

- **G3 (Hunter/Mapper 교차 일치) → ○ 즉시 가능.** 학습도 OCR 도 필요 없다. 우리
  `extract()` 는 문서 전체를 훑어 필드별 후보를 내므로 **Mapper 그 자체**이고,
  `reread()` 는 필드 하나를 크롭에서 다시 읽으므로 **Hunter 에 해당**한다. 지금은
  재판독을 "실패했을 때만" 부르는데, **MVP 9필드에 대해서는 항상 부르고 일치 여부를
  신호로 쓰면 된다.**
  ⚠️ 단 논문에 **G3 단독 AUC 수치는 없다.** M4(G2 단독) 0.896 은 OCR 신호 값이지 교차
  일치 값이 아니다. 우리 골든셋에서 직접 재야 한다.
- **G2 (OCR verbatim) → △ 조건부.** 텍스트 레이어가 있는 문서에만. tif 제외.
- **G4 라플라시안 선명도 → ○ 즉시 가능.** OpenCV 없이 PIL + 간단한 커널로 계산되고,
  이미 `_crop()` 이 만드는 크롭에 그대로 적용된다.
- **G1 로그확률 → × 보류.** 우리 tier 모델(`gpt-5.6-luna`/`terra`)의 `logprobs` 지원
  여부가 미확인이고, M1 0.880 은 매력적이지만 G2 없이 단독으로 0.880 이 재현될지는
  문서 종류가 달라 알 수 없다.
- **CatBoost 결합 → × 보류.** 1,072 표본으로 학습한 40특징 모델을 840(실질 더 적음)
  표본에 옮기면 과적합한다. 대신 **신호 3~4개의 규칙 결합 또는 로지스틱 회귀**로 시작한다.
- **isotonic 보정 → △.** M7 이 ECE 를 0.199 → 0.034 로 낮춘 건 크다. 다만 보정용
  홀드아웃이 따로 필요해 30건 골든셋에서 배분 설계가 필요하다(§7).

**논문이 밝힌 한계** — *"ExtractConf 는 명시적 OCR 파이프라인 출력을 필요로 한다.
평가는 영문 비즈니스 문서에 한정된다. LLM 백본은 하나만 테스트했다."*

**우리 골든셋으로 재는 법** → §6 실험 E2.

### R2. VLM OCR 오류 회피 벤치마크
[arXiv:2511.19806](https://arxiv.org/abs/2511.19806)

**무엇을 한 연구인가.** VLM 이 글자를 잘못 읽었을 때 "이건 못 읽겠다" 고 스스로 기권하게
만드는 방법 8가지를 같은 조건에서 비교.

**abstention accuracy 정의** — 임계 τ 에서 맞는 답은 채택하고 틀린 답은 기권하는 비율.

```
A-Acc = (1/N) Σ [ I(s_i < τ)·(1 - y_i)  +  I(s_i ≥ τ)·y_i ]
```

**실험 조건**

| 데이터셋 | 규모 | 성격 |
|---|---|---|
| OCRBench v2 | 10K QA | 텍스트 인식·위치·문서 VQA·요소 파싱 |
| SEED-Bench-2-Plus | 2.3K | 차트·지도·웹 화면 |
| HierText | 11K 이미지 | 야외 장면 텍스트 |
| EgoTextVQA | 1.5K 클립 | 1인칭 영상 텍스트 |

모델: **Qwen2.5-VL-7B, Gemma3-12B — 오픈소스 2종뿐.**

**수치**

| 방법 | Qwen2.5-VL-7B | Gemma3-12B | 4벤치 평균 |
|---|---|---|---|
| VLM Judge | 0.768 | 0.760 | 0.722 |
| Self Consistency (5샘플) | 0.677 | 0.743 | 0.646 |
| Token Probability | 0.665 | 0.700 | 0.669 |
| Ask for Calibration (**자기보고**) | — | — | **0.604** |
| Prompt to Abstain | — | — | 0.427 |
| 제안 방법 Ensemble(Hidden) | **0.789** | **0.797** | — |

각 방법의 실제 구현:

| 방법 | 구현 |
|---|---|
| Token Probability | `s = exp((1/n) Σ log p_i)` — 생성 토큰 평균 확률 |
| Ask for Calibration | 답변 후 *"1~5 스케일로 확신도를 평가하라"* 라고 되묻기 |
| Self Consistency | 5회 샘플링 후 문자 정확도(CA) 기준 다수결 |
| VLM Judge | 별도 VLM 이 답의 정오를 True/False 확률로 판정 |

**우리와 다른 점 (중요)**

- 과제가 **VQA·장면 텍스트**다. 우리의 "양식 문서에서 지정 필드 뽑기" 와 형태가 다르다.
- 모델이 **오픈소스 2종**뿐이다. GPT·Claude 는 없다.
- 제안 방법(LRP·Ensemble)은 **은닉 상태와 어텐션 가중치**를 쓴다 — OpenAI API 에서는
  꺼낼 수 없으므로 **우리에겐 적용 불가**다.

**이식 판정 — △ 순서만 가져온다.** 절대 수치를 우리 과제에 옮기면 안 된다. 하지만
**순위는 두 모델·두 집계 방식에서 모두 안정적**이다:

> VLM Judge > Self Consistency > Token Probability > **Ask for Calibration(자기보고)**
> > Prompt to Abstain

우리가 지금 쓰는 것이 목록의 **아래에서 두 번째**라는 사실이 이 논문의 우리에 대한 결론이다.
그리고 우리가 쓸 수 있는 것 중 가장 위가 **VLM Judge** 인데, 그것이 곧 §2 의 R7(평가 Agent)이다.

### R3. 스캔 금융문서 다단계 파이프라인 (KYC 실무)
[arXiv:2604.26462](https://arxiv.org/abs/2604.26462) · 우리 파이프라인과 형태가 가장 닮음

**무엇을 한 연구인가.** 저해상도·기울어짐·노이즈가 있는 **스캔** 금융문서에서 지정 필드를
뽑는 실무 파이프라인. 전처리 → OCR → 페이지 검색 → 소형 VLM 추출 → 사람 확인.

**실험 조건**

| 항목 | 값 |
|---|---|
| 문서 | 120건 (감사보고서 89 + 급여명세서 31), **약 3,000 스캔 페이지** |
| 언어 | 영어 57% · 중국어 간체 18% · 인도네시아어 15% · 번체 10% |
| 필드 | **12개** (감사보고서 7 + 급여명세서 5) |
| 정확도 정의 | 정규화 후 **완전일치**만 정답 |
| VLM | MiniCPM-o-2.6 · Gemma-3-27b-it · Qwen3-VL-8B (**전부 소형/오픈**) |
| OCR | PaddleOCRv3 또는 EasyOCR |
| 페이지 검색 | **BM25 + 문장 임베딩 하이브리드** |

**ablation 표 전체** (단위 %)

| OCR | VLM | 전체 | −전처리 | −페이지검색 | −구조화프롬프트 | 문서 통째 직접투입 |
|---|---|---|---|---|---|---|
| PaddleOCR | MiniCPM-o-2.6 | **87.27** | 71.00 | 63.25 | 84.38 | 55.38 |
| PaddleOCR | Gemma-3-27b-it | 72.97 | 60.89 | 52.10 | 72.57 | 47.64 |
| PaddleOCR | Qwen3-VL-8B | 85.30 | 77.17 | 63.78 | 80.97 | 55.91 |
| EasyOCR | MiniCPM-o-2.6 | 75.20 | 67.59 | 59.45 | 74.28 | 54.20 |
| EasyOCR | Gemma-3-27b-it | 65.09 | 58.92 | 48.29 | 64.30 | 47.51 |

읽는 법:

- **페이지 검색 제거 → 15.75 ~ 24.02%p 하락.** 다섯 행 전부에서 가장 큰 하락. 검색은
  VLM 에 보내는 페이지를 **평균 약 70% 줄인다.**
- **전처리 제거 → 6.17 ~ 16.27%p 하락.**
- **구조화 프롬프트 제거 → 0.40 ~ 4.33%p 하락** (항상 나빠진다. rev.1 정정 1)
- **OCR 엔진 교체만으로 12.07%p** 차이 (PaddleOCR 87.27 vs EasyOCR 75.20, 같은 VLM).

**우리와 다른 점**

| | 논문 | 우리 |
|---|---|---|
| 필드 수 | 12 | **28 (MVP 9)** |
| VLM | 소형 오픈모델 | GPT tier1/tier2 |
| "직접 투입" 기준선 | 소형 VLM 에 수십~수백 페이지 통째 | 우리는 애초에 페이지를 고른다 |
| 페이지 선택 근거 | 내용 유사도(BM25+임베딩) | **최신성**(날짜·개정표기) — 우리 쪽이 도메인 특화 |

**이식 판정 — ○ 이미 하고 있다. 새로 할 것은 없고, 근거로 쓴다.**

세 가지 확인을 준다.
1. §4.2 페이지 선택은 비용 장치가 아니라 **정확도 최대 레버**다. `pick_latest_spec()` 이
   못 가릴 때 `None` 을 돌려 사람에게 넘기는 설계가 정당하다.
2. `deskew=False` 기본값은 **바꿀 근거가 생겼다** (전처리 제거 시 6~16%p).
3. 긴 구조화 `SYSTEM` 프롬프트는 **유지가 맞다.**

⚠️ 단서 — "직접 투입 55%" 는 **소형 오픈 VLM 에 수십 페이지를 통째로** 넣은 값이다.
GPT 급 모델에 한 페이지를 넣는 우리 조건과 다르므로, **"우리도 안 하면 55% 다" 로 옮겨
말하면 안 된다.** 옮길 수 있는 건 각 단계의 **기여도 순위**뿐이다.

**저자가 밝힌 실패 원인** (우리와 겹치는 것에 표시)

- 용어 불일치 — *수익 / 소득 / 판매* 가 뒤섞여 검색·매핑 실패 → **겹침.** 우리
  `Valve Coefficient` vs `RATED CV` 문제와 같다. `fields.yaml` 의 aliases 가 이 대응책이다.
- OCR 오류 — 저품질 스캔·필기·겹침으로 텍스트가 깨져 **페이지 검색 자체가 실패** → **겹침**
- 통화 단위 모호성 (`IDR'000`, `ribuan`) → **겹침.** 우리 `H`/`Hr`/`hr` 문제(§4.6)와 같은 종류

### R4. olmOCR — document anchoring
[arXiv:2502.18443](https://arxiv.org/abs/2502.18443)

**무엇을 한 연구인가.** PDF 바이너리에서 텍스트 블록·이미지의 **좌표와 텍스트를 뽑아
프롬프트에 함께 넣고**, 렌더 이미지와 같이 VLM 에 준다. 7B 모델을 26만 페이지로 파인튜닝.

**프롬프트 형식** (Appendix A)

```
RAW_TEXT_START
{base_text}
RAW_TEXT_END
```

`base_text` 는 페이지에서 뽑은 텍스트 블록·이미지에 **위치 정보를 붙인 것**이다. 문서
시작·끝 요소를 우선 담고 **문자수 상한(파인튜닝 시 6,000자)** 에서 자른다.

**수치**

| 항목 | 값 |
|---|---|
| GPT-4o 교사와의 alignment | 0.875 (τ=0.1) / GPT-4o 자기일치 0.954 |
| 사람 평가 ELO | 1800+ |
| 비용 | 100만 페이지 $190 (GPT-4o 배치 $6,240 대비 32배 저렴) |
| **anchoring 정량 ablation** | **없음** |

**실패 대응 (우리와 직접 비교 가치 있음)** — 최빈 실패는 **같은 토큰·줄·문단의 무한 반복**.
최대 컨텍스트 초과 또는 **JSON 스키마 검증 실패**로 잡아낸다. 잡히면 temperature 0.1 → 0.8
로 올리고 앵커를 다시 샘플링해 재시도, 끝내 실패하면 순수 텍스트 추출로 폴백.

**우리와 다른 점 — 결정적**

저자 원문: *"document-anchoring 은 born-digital 문서의 품질에 도움이 되지만, 디지털
메타데이터가 전혀 인코딩돼 있지 않은 문서에서도 파이프라인은 높은 성능을 유지한다. 그런
경우 모델은 PDF 내부 구조를 보지 못하고 **래스터 이미지에만 의존한다.**"*

즉 **anchoring 은 born-digital 전용 장치**다. 우리 tif 734건은 해당 없음.

**이식 판정**

- 텍스트 레이어 있는 PDF·xlsx → **△ 시도 가치 있음.** §10 의 "VLM+텍스트" 칸의 구현이 된다.
  단 **논문에 정량 근거가 없으므로 우리 골든셋에서 직접 재야 한다.**
- tif → **× 적용 불가.**
- **반복 붕괴 방어 → ○ 즉시.** 우리 `_ask()` 는 JSON 파싱 실패 시 예외를 올려 같은 방어를
  이미 한다. 다만 **길이 초과로 잘린 JSON** 과 **형식 오류**가 구분되지 않는다.
  `finish_reason == "length"` 를 따로 기록하면 실패 원인 통계가 나뉜다 (철학 5).

### R5. VERDI — 구조화 출력에서의 로그확률 포화
[arXiv:2605.11334](https://arxiv.org/abs/2605.11334)

**관찰의 정확한 조건**: GPT-4.1-mini, SummEval·FEVER, **구조화 JSON 출력**, **answer
토큰(yes/no)** 의 로그확률.

> *"with structured JSON output (the standard for automated evaluation), we observe that
> 99.4–100% of logprobs saturate to values above 0.999 across SummEval and FEVER"*

**이식 판정 — 우리 조건과 다르다 (rev.1 정정 3).** 우리는 yes/no 가 아니라 문서에서

confidence 든)는 "얼마나 확신하는지" 가 아니라 "형식을 얼마나 잘 따랐는지" 를 재기 쉽다.**
우리 조건에 더 맞는 수치는 R1 의 로그확률 평균 AUC 0.705 다.

### R6. ExStrucTiny — 스키마 가변 구조화 추출 벤치마크

### R7. 채점 LLM 분리 — 추출자와 채점자를 나눈다
[arXiv:2510.19334](https://arxiv.org/abs/2510.19334)

**무엇을 한 연구인가.** 추출 에이전트가 뽑은 값을, **같은 문서 + 뽑힌 값**을 함께 받은
별도 LLM 이 채점한다.

**실험 조건** — CUAD 계약서 500건 이상, 8개 메타데이터 범주 (별도 내부 임대차 계약
40필드). 모델 Claude 3.5 Sonnet · Gemini 1.5 Flash · GPT-4o · Text-Unicorn.

**수치 (Table 4)**

| | 추출 에이전트 | 채점 LLM |
|---|---|---|
| 전체 케이스 | 73.3% | **80.5%** |
| **어려운 케이스** | 61.1% | **76.6%** |

**저자 설명** — 채점 LLM 은 **이미 뽑힌 후보를 갖고 시작**하므로, 문제가 "열린 추출" 에서
"검증과 수정" 으로 바뀐다. 후보를 따져보는 것이 맨바닥에서 찾는 것보다 인지적으로 쉽다.

**우리와 다른 점 / 주의**

- 논문의 채점 LLM 은 **필드별 0~1 점수와 함께 '수정된 값' 까지 낸다.**
- 우리 규칙은 *"재시도 프롬프트에 값이 틀렸다고 쓰지 않는다"* 이다(CLAUDE.md).
  **긴장이 있다.** 다만 성격이 다르다 — 금지된 것은 *"네 답이 틀렸으니 다시 답하라"* 는
  **되묻기**이고, 채점자는 문서를 직접 보고 **독립적으로 판정**한다. 그래도 안전하게 가려면
  **점수만 받고 수정값은 받지 않는 형태**로 이식한다. 수정이 필요하면 REVIEW 로 넘긴다.

**이식 판정 — ○ 즉시 가능.** ⑤ Validate 의 '평가 Agent' 칸이 이미 비용 사다리에 있다.
R2 에서 **VLM Judge 가 우리가 쓸 수 있는 방법 중 가장 높았다**(0.760~0.768)는 것과
같은 방향을 가리킨다. 비용은 필드당 호출이 아니라 **문서당 1회 채점**으로 묶으면 감당된다.

## 5. 새로 발견한 리스크 — bbox 를 믿고 있다

**사실.** 최고 성능 폐쇄형 모델도 문서 필드의 bbox 를 **IoU 14.4%** 로 찍는다. 페이지는
84.3% 로 맞히고 근접성은 74.8% 인데, **정확한 상자는 못 그린다** (R6 Table 6).

**우리가 bbox 에 의존하는 곳 세 군데**

1. `src/ui` HITL 화면의 하이라이트 — 사람이 근거를 확인하는 수단
2. `reread()` 의 크롭 — **재판독의 입력 자체**
3. (계획 중) 신뢰도 신호로서의 라벨 근접성

**무엇이 잘못될 수 있나.** bbox 가 어긋나면 `_crop()` 이 **엉뚱한 영역을 잘라** 재판독에
넘긴다. 그러면 재판독 결과가 원래 값과 다르게 나오고, 우리는 그것을 **"값이 의심스럽다"**
로 해석하게 된다. 실제로는 **"상자가 틀렸다"** 인데.

**대응 (구현 비용 작음)**

- `_crop()` 의 우측·상하 여백 0.02 는 IoU 14.4% 환경에서 너무 좁다. **여백을 키우고
  최소 크롭 크기를 둔다.** 좌측 0.10 은 라벨을 담으려는 의도라 맞다.
- 재판독 결과가 다를 때 **두 가지를 구분한다** — 크롭 안에서 원래 값의 라벨(`raw_label`)이
  보이면 "값 불일치", 라벨조차 안 보이면 **"bbox 오류"** 로 별도 분류한다. 후자는 값을
  의심할 근거가 아니다.
- 화면에서 하이라이트를 **점이 아니라 영역 힌트**로 보여주고, 어긋날 수 있음을 문구로 남긴다.
- 골든셋 30건에서 **bbox 를 눈으로 검수해 우리 코퍼스의 실제 IoU 를 한 번 재둔다.** 공개
  벤치와 다를 수 있고, 이 숫자가 있어야 위 여백값을 근거 있게 정한다.

## 6. 검증 설계 — 무엇을 돌려서 무엇을 보면 판단이 되는가

전부 `eval/harness.py` 와 골든셋 30건 위에서 돈다. **API 없이 되는 것과 있어야 되는 것**을
나눴다.

| ID | 실험 | 돌리는 것 | 보는 숫자 | 판단 기준 |
|---|---|---|---|---|
| **E1** | 자기보고 confidence 가 쓸모 있나 | 골든셋 전량 1회 추출, confidence 와 정오를 함께 기록 | **AUC**, confidence 값의 분포(히스토그램) | AUC 가 0.70 을 밑돌거나 값이 0.9/0.95/1.0 에 뭉치면 **단독 사용 폐기** |
| **E2** | 교차 일치가 신호가 되나 | MVP 9필드에 대해 `reread()` 를 **항상** 호출, 1차값과 비교 | 일치/불일치 각 집단의 실제 정답률 | 불일치 집단 정답률이 일치 집단보다 뚜렷이 낮으면 **채택** |
| **E3** | 텍스트 verbatim 대조가 신호가 되나 | 텍스트 레이어 있는 문서만 대상, 추출값이 페이지 텍스트에 있는지 퍼지 대조(50/75/90%) | 같은 방식의 집단별 정답률, AUC | E1 AUC 대비 개선폭 |
| **E4** | 신호 결합의 이득 | E1~E3 신호를 로지스틱 회귀로 결합 (특징 3~5개) | AUC, **커버리지-정확도 곡선** | 곡선에서 "자동확정 X%일 때 정확도 Y%" 를 읽어 **임계 확정** |
| **E5** | `deskew` 기본값 | on/off 각 1회 | MVP 9필드 정확도 | 유의한 차이가 있으면 기본값 변경 |
| **E6** | 필드 수 영향 | `only_mvp=True/False` 각 1회 | **MVP 9필드만의** 정확도 비교 | 9필드 단독이 뚜렷이 높으면 필드 분할 검토 |
| **E7** | 텍스트 앵커링 | 텍스트 레이어 있는 문서에 `RAW_TEXT_START/END` 동봉 | 정확도 · N/A 비율 | §10 3-way A/B 의 "VLM+텍스트" 칸을 이걸로 채운다 |
| **E8** | bbox 실측 | 골든셋 bbox 를 사람이 검수 | 우리 코퍼스의 IoU · 라벨 포함률 | `_crop()` 여백값의 근거 |

**순서.** E1 → E2 → E4 가 본줄기다. E1 하나만 돌려도 "지금 임계가 의미 있나" 에 답이 나온다.
E5·E6 는 독립이라 언제 돌려도 된다. E3·E7 은 텍스트 레이어 경로에만 해당한다.

**비용 개산.** E2 가 문서당 9회 재판독을 추가한다. 크롭은 페이지 전체보다 훨씬 작으므로
입력 토큰은 작고, 골든셋 30건 기준 270회다. tier1 모델로 돈다.

**주의 — 홀드아웃.** §10 이 골든셋 일부를 개발 중 보지 않기로 잠갔다. E4 의 결합 가중치를
학습하면 **그 데이터로 임계를 정한 것**이 되므로, 학습용과 임계 확정용을 나눠야 한다.
30건에서 이걸 하려면 배분 설계가 필요하다 — §7 의 1번.

## 7. 추가 조사가 필요한 영역

1. **30건 골든셋으로 신뢰도 보정이 되는가.** R1 은 필드 단위 1,072표본으로 CatBoost 를
   학습했다. 우리는 최대 840(홀드아웃·N/A 제외하면 더 적음)이다. 특징 수를 3~5개로 줄이고
   필드 유형별로 묶어야 하는데, 그래도 학습·보정·평가 3분할이 가능한지 계산이 필요하다.
2. **우리 tier 모델의 `logprobs` 지원 여부.** `gpt-5.6-luna`/`terra` 가 vision + JSON
   출력에서 `logprobs=True` 를 받는지 확인되지 않았다. 되면 R1 의 G1 신호가 열린다.
3. **tif 경로에 텍스트 근거를 줄 방법.** 지금은 없다. 로컬 OCR 추가가 정공법이지만 이번
   범위 밖이다. **골든셋 30건에 대해서만 한 번 OCR 을 돌려 E3 의 효과 상한을 재보는 것**은
   가능하고, 그 숫자가 후속 과제의 근거가 된다.
4. **OpenAI Batch API 와 prompt caching 병용 조건.** 1,021건 처리 비용과 직결되는데
   커뮤니티 정보가 엇갈린다. `src/models.py` 가 prompt caching 을 전제로 설계돼 있으므로
   공식 문서 확인이 필요하다.
5. **1비트 150DPI 팩스 스캔에 대한 공개 근거 부재.** 우리 코퍼스의 지배적 형태인데 어느
   벤치마크에도 없다. 이 자체가 발표에서 말할 값어치가 있는 관찰이다.
