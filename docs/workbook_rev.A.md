### 작성 원칙

현재 업무와 의사결정을 먼저 적고, AI·LLM·강화학습 같은 방법론은 뒤에 비교한다.

확인된 사실과 가정을 구분하고, 미확인 사항은 추가 확인 질문으로 남긴다.

모델 성능뿐 아니라 실제 사용자, 업무 반영 지점, 운영 KPI를 함께 정의한다.

AI가 최선의 방법이 아닌 것으로 분석되면 데이터 정비, 규칙 표준화, 최적화, 시뮬레이션 등을 선택한다.

### A-2. 현재 문제 상황

| 확인 질문 | 작성 |
|---|---|
| 현재 누가 어떤 방식으로 업무를 수행하는가? | 설비 엔지니어 30명이 벤더 데이터시트를 육안 판독하여 마스터DB 항목에 직접 입력함.<br>문서는 스캔 이미지 30% / 텍스트 PDF 30% / 엑셀 40%로 혼재하고, 벤더 5개사 이상의 양식·표기·단위가 표준화되어 있지 않아 정규화 판단을 사람이 매 건 수행함.<br>컨트롤밸브 1건당 이미지 2시간 / 텍스트 PDF 약 1.5시간(가정값) / 엑셀 1시간이 소요되며, 인당 월 20건 이상(신규+변경) 처리하여 부서 전체 월 600건에 이름.<br>입력 후 입력자 본인 1차 승인 → 도면관리 담당자 최종 승인의 2단계를 거침. |
| 반복되는 불편·지연·위험·재작업은 무엇인가? | ① 판독·정규화의 전면 수기 의존 — 동일 사양이 벤더별로 다르게 표기됨. 특히 Fail Action은 데이터시트에 Air-to-Open/Close로 기재되어 Fail Close/Open으로 역전 변환해야 하며, 이런 도메인 규칙이 개인 숙련도에 의존함<br>② 선택적 누락 — 필드 중요도에 대한 인식 차이와 입력 부담이 겹쳐 누락·오기가 축적됨. 필드 누락·오류율 40% 이상(현업 체감 추정치)<br>③ 재작업의 구조화 — 오류율이 임계치를 넘어서면서 현장이 DB를 신뢰하지 않고 거의 100% 원본 문서를 재확인함. 입력 공수와 재확인 공수를 이중 지출하는 구조가 고착됨<br>④ 기술 변화 미반영 — 스마트 포지셔너 확산으로 통신 프로토콜·진단 지원 등급 같은 신규 사양이 발생했으나 기존 스키마에 담을 자리가 없음<br>⑤ 위 문제들이 자기강화 루프를 형성함 — 이것이 문제의 실제 구조임<br>    데이터 미활용 → 품질 요구 부재 → 거버넌스·표준 미수립 → 누락·오류 40% → 신뢰도 붕괴 → 현장 원본 재확인 100% → (다시) 데이터 미활용<br>    개별 담당자의 성실성 문제가 아님. 소비자가 없는 데이터에는 품질 압력이 발생하지 않고, 품질이 낮으면 소비자가 더 줄어드는 구조임. 따라서 입력 자동화만으로는 해결되지 않으며, 루프를 끊는 지점(품질 보장 + 소비 가능한 신뢰 수준 확보)을 함께 설계해야 함 |
| 이 문제로 발생하는 손실 또는 리스크는 무엇인가? | [정량 — 유입분] 건당 172,500원(프로젝트 일괄 반영 100,000원 + 인건비 1.45h × 50,000원) × 월 600건 = 월 1.04억원 / 연 12.42억원. 상시 5.2 FTE(엔지니어 30명 중 17%)가 투입됨. 이 중 40%가 오류이므로 연 약 5억원이 직접 폐기되고, 산출물 활용률이 0%이므로 실질적으로 연 12.42억원 전액이 회수되지 않음<br>[정량 — 전량] 미정비 전량 30만 태그를 현행 방식으로 처리하면 435,000시간 = 216 FTE-년 = 517.5억원임. 현행 실제 처리 속도(연 7,200건) 기준으로는 41.7년이 소요되고, 엔지니어 30명 전원을 이 업무에만 투입해도 7.2년이 필요함. 개선 과제가 아니라 착수 가능성의 문제임<br>[안전 리스크] Fail Action 등 안전 관련 사양의 오류는 비상 시 밸브 거동 판단 오류로 이어질 수 있음<br>[전략 리스크] 예지보전·디지털트윈이 정확한 기준정보를 전제하므로, 현 상태에서는 후속 AI 과제 착수 자체가 불가함<br>※ 오류율 40%는 현업 체감 추정치이며 실측 이력이 없음. PoC 중 골든셋 100건 대조로 실측 확정 예정임 |
| 왜 지금 이 문제를 다루어야 하는가? | ① 처음으로 이 데이터의 소비자가 생김 — 디지털트윈 모델 구축 사전작업이 착수됨. 지금까지 기준정보는 활용되지 않았고 그래서 품질 요구도 거버넌스도 발생하지 않았음. 디지털트윈은 정확한 기준정보를 전제하므로, 미활용 → 품질 요구 부재 → 품질 저하의 악순환이 끊어지는 최초 시점이 지금임<br>② 개선 대상이 아니라 착수 조건임 — 전량 30만 태그를 현행 방식으로 정비하면 실제 처리 속도 기준 41.7년(전원 전담 시 7.2년, 517.5억원)임. 인력 증원으로 해결되는 규모가 아니므로, 방식을 바꾸지 않으면 디지털트윈 과제 자체가 성립하지 않음<br>③ 기술 장애물이 해소됨 — 2021년 최대 장벽이었던 하드카피·스캔 문서 판독이 Vision AI 성능 향상으로 실무 적용 가능 수준에 도달함. 당시 저ROI 유지보수로 인식되던 데이터 정비가 AI 자산관리의 선행 인프라로 재정의됨<br>④ 손실이 진행 중임 — 스마트 포지셔너 확산으로 수집 가능한 진단 데이터는 늘고 있으나, 기준정보에 통신 프로토콜·진단 지원 등급 항목이 없어 활용하지 못함. 지연될수록 신규 설비의 미반영분이 누적됨 |

| 보조 기능 2 | 분류·판단 (양식 변종·연식 판정 + 범주형 표준 코드 분류) | 양식 변종 15종과 레거시 혼재 조건에서 처리 경로를 분기하고 양식별·연식별로 정확도를 분리 관리하기 위해 선행되어야 함. 이것 없이 단일 정확도만 측정하면 전량(레거시) 적용 시의 성능 저하를 사전에 탐지할 수 없음<br><br>[범위 정리]<br>· 생성형 AI는 정규화·요약에서 보조적으로 사용하되 값 결정 권한을 부여하지 않음(허용값 리스트 내 선택 + 결정론적 단위 변환). 검색은 파생 3필드 매핑에 국한함. 두 기능 모두 독립 기능으로 세우지 않고 주 기능·보조 기능 내부 구성요소로 배치함<br>· 에이전트·BPM은 PoC 보조 기능이자 후속 핵심 기능임. PoC에서는 순차 파이프라인으로 구현하되 도구 단위 분리를 아키텍처 요건으로 강제하여 전환 경로를 확보함. 지속 실행·검증·개선 루프 구조 요구사항과도 연결됨<br>· 강화학습은 보류하고 후속 확장 조건에 배치함<br>· 추정 입력 금지 원칙: AI는 값을 제안하되 근거를 찾지 못한 경우 추정값을 생성하지 않고 'N/A + 비고'로 반환함. 확신도가 낮은 경우에는 제안값과 함께 '리뷰필요'를 표시함. 회사 기준정보 입력 원칙(모르면 채우지 않음)과 일치하며, 오적재보다 미확정이 안전하다는 판단에 근거함 |

### K-3. 과제 개요 요약

| 항목 | 요약 |
|---|---|
| 문제명 | 설비 기준정보(Master Data) 적재 업무의 수기 판독 의존 및 데이터 신뢰도 붕괴 |
| 핵심 사용자 | 설비 엔지니어 30명(입력·1차 검토), 도면관리 담당자(최종 승인), 디지털트윈·정비계획 담당자(결과 소비) |
| 핵심 의사결정/업무 | 비정형 벤더 데이터시트를 판독하여 마스터DB 필드값을 결정·정규화하고 승인하는 판단 — 문서·자산 매칭, 값 위치 판단, 표기 정규화, 도메인 규칙 적용, 결측 처리, 상충 해소 |
| 가장 중요한 데이터 | 벤더 컨트롤밸브 데이터시트 (이미지 30% / 텍스트 PDF 30% / 엑셀 40%, 벤더 5개사 · 양식 최대 15변종 · 현행 70% + 레거시 30%)<br>+ 컨트롤밸브 기준정보 스키마 정의서 및 정규화·변환 규칙표 (현재 미문서화 — 선행조건 1순위) |
| 주 접근법 | 멀티모달 LLM(VLM) 기반 정보추출 + 규칙 기반 검증 계층의 결합<br>보조: 데이터 정비(선행), 분류(양식·연식 라우팅), 에이전트·BPM(전환 경로 확보)<br>보류: 전통 ML(학습 데이터 부족), 강화학습(누적 피드백 부재) |
| 목표 KPI | 안전·식별 필드 오적재 0건 / 직접 추출 16필드 정확도 95% 이상(목표 98%) / 자동확정률 50% 이상 / 건당 처리시간 0.7시간 이하(1.45h 대비 52% 절감) / 필드 누락·오류율 5% 이하(현행 40% 추정) |
| 가장 큰 리스크 | ① 기준정보 거버넌스 주체 부재 — PoC가 성공해도 결과를 반영할 승인 경로가 없음. 스키마 정의서 확정 주체 불명확함<br>② 안전 필드 오적재 — 100건 표본으로는 100% 수준을 통계적으로 입증할 수 없어, 규칙 검증·강제 확인·근거 병기의 3중 설계로 대응함<br>③ 문서 외부 반출 승인 불가 — 발생 시 온프렘으로 방법론 전면 재설계 |
| PoC 검증 항목 | H2 안전 보장(오적재 0건, 최우선) / H1 추출 성능(16필드 95% 이상) / H3 공수 절감(0.7h 이하) / H4 현행 오류율 실측(체감 40% 검증) / H5 방법론 정당성(VLM 대 규칙 단독 비교)<br>대상: 컨트롤밸브 1,000건 + 골든 100건(개발 30 / 홀드아웃 70) / 기간 8일 / 2026-08-27 발표 |
