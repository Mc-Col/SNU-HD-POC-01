### C011 · 강화학습 배치 결정 ★
- **요청자** 사용자 질의 → AI 판단 → 사용자 수용

**설계 결정 4건**

1. **PNG, JPG 아님** — 1비트 150DPI 손글씨 스캔에서 JPG 손실압축 잡티가 판독을 방해. 1비트는 그레이스케일로 올려 렌더
2. **엑셀은 시트 1개 = PNG 1장** — 통째로 내보내니 5시트가 인쇄면 13장이 되어 `probe_pages()` 의 시트 번호와 어긋났다(`has_text_layer` 는 시트 기준, `render_path` 는 인쇄면 기준 → **계약 버그**). 엑셀의 의미 단위는 인쇄면이 아니라 시트이므로 시트마다 따로 `ExportAsFixedFormat`. 실물 확인: Metso 93행 사양표가 A4 가로 한 장에 완전히 읽히게 들어감
3. **격자는 12칸씩 분할** — Claude 는 긴 변 1568px 초과 시 이미지를 축소한다. 최대 61페이지 파일을 한 장에 담으면 셀이 224px 로 줄어 판독 불가. 3x4=1440px 가 한계 안 최대치
4. **엑셀 렌더 실패는 예외를 던지지 않음** — 빈 목록을 돌려주고 Triage 가 판정. 전처리 도구가 파이프라인을 죽이지 않게

### C031 · 태그 규칙 반영 — Area 생략은 A ★★
- **요청자** 사용자 (*"B는 태그의 일부야. Tag name rule에 따르면, 맨앞은 Area거든. 아무 알파뱃이 없으면 A가 생략된거야. 1공장은 최초의 공장이라 처음 지을때는 알파뱃이 필요없었어... 그러다가 2공장이 생기고 공장간 구분이 필요해져서, 거기부터 B를 붙이기 시작한것"*)
- **경과** C030 의 미해결 항목(`070055_REV0.pdf` 의 `B10-PV-1631A` 에서 `B` 의 정체)에 대한 도메인 답

**규칙**

```
[Area][Unit]-[Type]-[Number][Suffix]        A10-FV-001 · B10-PV-1631A
 └ 맨 앞 알파벳 한 자. 없으면 A 가 생략된 것.
   1공장이 최초 공장이라 지을 때 공장 구분이 필요 없었고, 2공장부터 B 를 붙였다.
```

**고친 버그 — 서로 다른 설비가 같은 값이 되고 있었다**

기존 `normalize_tag()` 는 앞의 문자를 버렸다. 그래서 `10-FV-012`(A구역)와 `B10-FV-012`(B구역)가 **둘 다 `10FV012`** 가 되어 서로 다른 밸브가 충돌했다.

현재 코퍼스에서는 충돌 **0건**(A구역 1,026 · B구역 19)이라 증상이 없었다. 잠재 버그였고, 30만 태그 마스터DB 에서는 반드시 터진다. 이 과제가 없애려는 문제(설비 식별 오염)를 그대로 재생산하는 종류의 버그다.

| | 이전 | 지금 |
|---|---|---|
| `10-FV-012` | `10FV012` | `A10FV012` |
| `A10-FV-012` | `10FV012` | `A10FV012` |
| `B10-FV-012` | `10FV012` ← 충돌 | `B10FV012` |
| `B10-PV-1631A` | `10PV1631A` ← `B` 소실 | `B10PV1631A` |

**정규화 키와 내보내는 값을 분리했다**

문서에 `10-FV-012` 라고 적혀 있으면 **내보내는 값은 `10-FV-012`** 다. 없는 `A` 를 만들어 넣지 않는다(철학 4). `A` 는 대조용 내부 키에만 넣는다.

| | 용도 | 값 |
|---|---|---|
| `TagParts.key` / `FileNameInfo.tag` | 파일명↔문서 대조, 페이지 검증 | `A10FV011` |
| `TagParts.raw` / `FileNameInfo.tag_raw` | 화면·엑셀 표시 | `10FV011` |
| `TagParts.implicit_area` | 원문에 Area 문자가 없어 A 로 채웠는가 | `True` |

**Type 을 2~4자로 제한**

1자를 허용하면 액추에이터 스프링 번호 `1E7924` 가 태그로 잡힌다. 실측상 1자 타입은 1,059건 중 **1건**(`B19V10-DATA SHEET_REV1.xlsx`)뿐이고, 그 파일은 문서 안 태그가 그냥 `V10` 이며 내용이 2010년 TA Retrofit 체크시트다. 즉 **파일명은 DATA SHEET 인데 내용은 정비보고서** — 파일명 문서종류가 항상 진실은 아니라는 반례이기도 하다. 태그 없음으로 두고 내용 판정으로 보낸다.

**나열 표기 펼치기 — 다중 설비 사양표 대조의 전제**

`10-FV-011 / 012 / 013 / 014` 에서 뒤 세 개는 번호만 적혀 있다. 펼치지 않으면 `10FV012` 파일이 이 페이지를 "내 태그가 없는 페이지" 로 판정해 확인필요로 떨어진다.

```
10-FV-011, 012, 013, 014      →  같음 (쉼표도)
B10-TV-481A / B               →  B10TV481A B10TV481B (접미만 바뀌는 나열)
```

**자리수가 같은 번호만** 이어 붙인다 — `10-FV-011 / 2003`(날짜)을 태그로 잡지 않기 위해서다. `Cv% / Signal% 8.2 / 17`, `Flow Rate 42.0 / 123.0 / 200.0` 같은 숫자 나열도 걸리지 않는다.

### C032 · 태그 규칙 정정 — Area 는 문자+숫자, B19 예외 기록 ★★

**규칙 보강 — 다중 시점과 다중 자산은 다른 문제다 ★**

`070100_REV0.pdf` 를 열어보고 `pick_latest_spec()` 의 빈틈을 발견했다.

| 페이지 | 내용 |
|---|---|
| p4 | Control Valve Specification — `B10-TV-040` |
| p5 | Control Valve Specification — `B10-TV-1016` |

사양표가 2장이지만 `10FV011`(같은 설비의 2003년/1986년)과 **성격이 완전히 다르다.** 이건 서로 다른 설비 2대다. 최신성으로 풀 문제가 아니다.

**판별자는 태그 교집합이다.**

```
10FV011  p1 태그 [011,012,013,014] · p4 태그 [011]  → 교집합 있음 → 같은 설비, 최신을 고른다
070100   p4 태그 [B10TV040] · p5 태그 [B10TV1016]   → 교집합 없음 → 다른 설비, 파일명 태그로 고른다
```

교집합이 비면 파일명 태그로 가르고, 파일명에도 태그가 없으면 **"자산 N건 발견"** 으로 사람에게 넘긴다(사용자가 정한 다중 자산 처리 방침과 일치).

이 보강으로 기존 fixture 2건이 실패했다. 확인해보니 **새 동작이 맞았다** — 태그가 완전히 분리된 두 페이지에서는 "2003년 타 설비 사양서" 보다 "1986년 내 설비 사양서" 가 답이다. 낡은 기대를 담고 있던 테스트를 두 규칙의 구분이 드러나도록 재작성했다:

- `[5-a]` 같은 설비 → 태그 단독성으로 고르지 않는다 (C028 회귀 방지)
- `[5-b]` 다른 설비 → 파일명 태그로 고른다. 최신성은 의미 없다 (C029 오적용 방지)
- `[5-c]` 선택 후 태그 검증

**루트 `pytest` 가 통째로 깨져 있었다 — `pytest.ini` 신설**

이 저장소에는 자체 검증 방식이 둘 섞여 있다.

```
pytest        src/<모듈>/test_*.py        (서경빈 선임)
단독 스크립트   fixtures/<모듈>/test_*.py   (이종수 책임)
```

단독 스크립트는 import 시점에 바로 돌고 `sys.exit()` 로 끝난다 — 비개발자도 파일 하나만 실행하면 결과가 보이게 하려는 의도다. 그런데 이름이 `test_*.py` 라서 pytest 가 수집하려 하고, 수집 중 `SystemExit` 이 나서 **루트에서 `pytest` 를 실행하면 `INTERNALERROR` 로 아무 테스트도 돌지 않았다.**

조원이 가장 자연스럽게 칠 명령이 통째로 죽어 있던 것이다. `pytest.ini` 로 수집 범위를 `src/` 로 제한했다. 두 방식을 통일하지 않은 이유는 각각의 목적이 다르기 때문이고, 이유를 파일 주석에 적었다.
