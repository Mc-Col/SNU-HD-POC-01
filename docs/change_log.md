### C011 · 강화학습 배치 결정 ★
- **요청자** 사용자 질의 → AI 판단 → 사용자 수용
- **사용자 질의** "강화학습을 과제 A에 녹일 요소가 있는가"

- **배치** Part D "조건부 적용 가능" / Part F "보류 + 이유" / Part J 후속 확장 ⑦. 진짜 자리는 로드맵 종착점(정비정책 최적화)

| `normalize_tag()` | `10FV012` = `10-FV-012` = `10 FV 012` | 파일명 태그와 문서 안 태그를 대조하는 전제. 이게 없으면 아래 페이지 선택 규칙이 성립하지 않음 |
| `probe_pages()` | 페이지별 텍스트 레이어 유무 | 임계 100자. PDF 파일의 57.4% 가 텍스트·스캔 혼재이므로 파일 단위 판정은 오답 |
| `render_pages()` | tif/pdf/xlsx → 페이지별 PNG | `pages=[1,4]` 로 필요한 장만 렌더 가능 |
| `make_montage()` | 썸네일 격자 → VLM 1회 판정 | 480px 셀에서 사양표·도면·부품리스트·표지·계산서가 구분됨(실물 확인). **태그 글자는 안 읽힘** |

**설계 결정 4건**

1. **PNG, JPG 아님** — 1비트 150DPI 손글씨 스캔에서 JPG 손실압축 잡티가 판독을 방해. 1비트는 그레이스케일로 올려 렌더
2. **엑셀은 시트 1개 = PNG 1장** — 통째로 내보내니 5시트가 인쇄면 13장이 되어 `probe_pages()` 의 시트 번호와 어긋났다(`has_text_layer` 는 시트 기준, `render_path` 는 인쇄면 기준 → **계약 버그**). 엑셀의 의미 단위는 인쇄면이 아니라 시트이므로 시트마다 따로 `ExportAsFixedFormat`. 실물 확인: Metso 93행 사양표가 A4 가로 한 장에 완전히 읽히게 들어감
3. **격자는 12칸씩 분할** — Claude 는 긴 변 1568px 초과 시 이미지를 축소한다. 최대 61페이지 파일을 한 장에 담으면 셀이 224px 로 줄어 판독 불가. 3x4=1440px 가 한계 안 최대치
4. **엑셀 렌더 실패는 예외를 던지지 않음** — 빈 목록을 돌려주고 Triage 가 판정. 전처리 도구가 파이프라인을 죽이지 않게

**부수 발견 — 페이지 선택 규칙이 나왔다 ★**

`10FV012-DATA SHEET_REV1.tif` 8페이지를 격자로 보니 사용자가 말한 구조가 그대로 확인됨:

| 페이지 | 종류 | 내용 |
|---|---|---|
| p1 | **spec** | Valstone 사양표 — `10-FV-011/012/013/014` **4개 태그 동시** |
| p2 | drawing | Outline drawing |
| p3 | cover | Masoneilan 표지 (Specifications & Drawings) |
| **p4** | **spec** | **Fisher 사양표 — `10-FV-012` 단독. 이것이 정답 페이지** |
| p5 | calc | Cv 계산서 (수기) |
| p6 | drawing | 치수도 |
| p7·p8 | bom | Spare parts list |

사양표가 2장이고, 정답은 **파일명 태그를 단독으로 담은 쪽**이다. 즉 파일명 태그는 메타데이터가 아니라 **페이지 선택의 판별자**다. VLM 의 주관 판단이 아니라 결정론적 규칙으로 고를 수 있다:

```
1) 격자 1장 → VLM 이진 판정: 어느 페이지가 사양표인가          (호출 1회)
2) 사양표가 1장이면 확정. 2장 이상이면 그 페이지만 원본 해상도로
   렌더 → 태그를 읽어 파일명 태그를 담은 페이지 선택            (호출 1~2회)
3) 확정 페이지에서 추출                                        (호출 1회)
```

8페이지를 VLM 8회가 아니라 **2~4회**로 처리한다. 태그가 헤더 좌상단에 고정이므로 2)를 크롭으로 더 줄일 수 있으나 최적화이므로 지금은 하지 않음

**Metso 엑셀 실물이 확증한 라벨링 결정 4건** — C027 및 라벨링 논의의 결정이 Fisher 외 벤더에서도 성립함을 확인

| 결정 | Metso 데이터시트의 실제 표기 |
|---|---|
| `POSITIONER TYPE` 삭제, 모델명만 | `Positioner Type: ELEC. PNEUMATIC` / `Model No. / Mfr.: AVP-302` — Type 은 전자·공압 구분값이지 모델명이 아님이 재확인 |
| 모델명은 `667-EZ` 식 결합 표기 | `Model Number: GU-VDR` (본체 `GU` + 액추에이터 `VDR`) — Fisher 의 `667-EZ` 와 동일 구조 |
| `REQUIRED CV` 는 NOR. 만 | `Required Cv: 1.16 / 2.51 / 12.2` (MIN/NOR/MAX) — NOR=2.51. `Rated Cv: 26` 은 별 칼럼 |
| `VALVE BODY TYPE` 신설 | `Type: GLOBE` 이 독립 행으로 존재 — 신설 판단이 맞았음 |

추가로 `Fail Position: CLOSE` 는 **직접 기재**형이라 `DefaultDomainValidate` 의 표기 일관성 검사(직접/역전) 양쪽 사례가 실물로 확보됨

**샘플 편중 경고** 지금까지 라벨링된 3건은 전부 Fisher·tif·레거시·1페이지 사양표다. 이 Metso 엑셀(5시트·현행·2페이지 사양표)처럼 **벤더·포맷·연식·사양표 위치**가 다른 건을 섞지 않으면 페이지 선택 정확도를 측정할 수 없다(항상 p1 을 고르는 코드가 100% 를 받는다)
